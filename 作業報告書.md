# 作業報告書 - Account SyncをSupabaseへ移行

## 目的

Cloudflare Worker経由ではosu! API v2へBearer Tokenを付けても429が継続したため、`web-project-guide` Guide Version `1.2.0` の外部Provider障害・GitHub中心運用ルールに従い、Account Syncの中継ProviderをSupabase Edge Functionsへ切り替えた。

Project Profile:

```text
STATIC + DATA + AI-HANDOFF + CLOUD + ELECTRON + TOOL
```

## 変更理由

本番E2Eで以下を確認した。

- Cloudflare Worker `/health`: 成功
- GitHub Actions runnerからosu! OAuth / API v2: 成功
- Cloudflare Worker → osu! API v2: HTTP 429

したがってosu! Client CredentialsやToken自体の不備ではなく、Cloudflare Worker経由の上流通信が問題となる構成を廃止した。

## Token Lifecycle

GitHub Repository Secrets:

```text
OSU_CLIENT_ID
OSU_CLIENT_SECRET
```

12時間ごとの `Refresh osu API Token` Workflowが:

1. `data/site.json`からSupabase endpointを取得
2. `refresh` actionへClient ID / Secretを一時送信
3. Edge Functionがosu! OAuth Tokenを発行
4. Access TokenだけをRLS保護Tableへ保存
5. `health`を確認
6. User ID 2でRecent Scores 1件E2E smoke

を実行する。

Client SecretはSupabase DBへ永続化しない。
