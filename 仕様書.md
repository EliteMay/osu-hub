## 3. システム構成

```text
GitHub Pages
   ↓ POST JSON
Supabase Edge Function: osu-sync
   ↓ Bearer Access Token
osu! API v2

GitHub Actions
   ↓ OSU_CLIENT_ID / OSU_CLIENT_SECRET
Supabase Edge Function refresh action
   ↓ Client Credentials

Browser IndexedDB
   ↑

```

Windows固有機能はElectron製 `osu Setup Launcher` が担当する。

## 4. Account Sync

入力:

- Supabase Sync API URL
- osu! User ID / username
- Ruleset
- 取得件数 1〜100
- Failを含める / 含めない

ブラウザへosu! Client ID / Client Secretを入力させない。

処理:

1. `health` actionでSync API確認
2. `configured=true` / `provider=supabase-edge-function` を確認
3. `sync` actionへ同期条件を送信
4. Edge FunctionがRLS保護テーブルからAccess Tokenを取得
5. osu! API v2 `Get User`を実行
6. `Get User Scores / recent`を実行
7. Edge Functionでosu! Hub用JSONへ正規化
8. Browser側でResponse再Validation
9. `id = osu:<score id>` を再生成
10. IndexedDB `results`へ保存
11. 同一Score IDは更新、手入力Resultsは維持

同期フィールド:

- Score / Beatmap / Beatmapset ID
- Map / Artist / Title / Difficulty / Mapper
- Date / Timestamp
- Accuracy / Miss / Combo / PP
- Star / BPM / AR / OD / CS / HP
- MOD / Rank / Pass / Fail / Replay / Total Score
- User ID / username / avatar / country / PP / rank / profile accuracy等の公開Statistics

## 5. Token Lifecycle

GitHub Repository Actions Secrets:

```text
OSU_CLIENT_ID
OSU_CLIENT_SECRET
```

`Refresh osu API Token` Workflow:

1. `data/site.json` からSupabase Function URLを取得
2. `refresh` actionへClient ID / Secretを一時送信
3. Edge Functionがosu! `/oauth/token` へClient Credentials Request
4. Token ResponseをValidation
5. Access Tokenだけを `public.osu_api_tokens` へ保存
6. `health` actionを確認
7. 公開User ID 2でRecent Scores 1件のE2E smoke test

Client SecretそのものはSupabase DBへ保存しない。Access Tokenをブラウザへ返さない。

Token table:

```text
public.osu_api_tokens
RLS: enabled
anon/authenticated: all privileges revoked
Edge Function: SUPABASE_SERVICE_ROLE_KEYでのみ読み書き
```

更新間隔は12時間。

## 6. External Reliability

- Browser timeout: 15秒
- Edge Function → osu! timeout: 12秒
- `response.ok`を確認
- timeout / upstream失敗時もLocalデータを削除しない
- 401 / 429を明示的に扱う
- `Retry-After`がある場合はResponseへ引き継ぐ
- 同一同期条件はEdge Function isolate内で60秒キャッシュ

Cloudflare Worker方式は、本番環境でBearer Token利用時もosu!側429を再現したため現行Runtimeから廃止した。Git履歴 / CHANGELOGにのみ履歴を残す。

```text
  results
  coaching
  practice
  settings
```

Import:

```text

→ 全体Validation
→ Recovery Snapshot

→ read-back verification
```
